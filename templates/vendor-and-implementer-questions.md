# Questions for vendors and implementers

Take this into the sales call and the statement-of-work review. Write the answer next to each question, and ask
for anything important to be written into the contract. The reasoning is in
[chapter 14](../14-working-with-vendors-and-implementers.md).

## The migration

| Question | Answer | In the SOW? |
| --- | --- | --- |
| Which records will you load, and which are we expected to load or re-key? | | |
| How many trial loads are included, and what does another one cost? | | |
| Can you load commitments with invoiced to date, paid to date and retainage per commitment, or only balances? | | |
| Can pay application numbering continue from our last application? | | |
| Can pending and rejected change orders be loaded with their status? | | |
| Can original budgets and approved changes be loaded separately? | | |
| After each load, will you give us the loaded data back as an export so we can reconcile it independently? | | |
| Who fixes load errors, how fast, and at whose cost? | | |
| Do we receive the mapping files and transformation scripts at the end? | | |
| Who is on call during the cutover window? | | |

## Our data

| Question | Answer | In the contract? |
| --- | --- | --- |
| Where is our data stored, and who can access it? | | |
| Which subprocessors handle our data? | | |
| How do we export all of our data, in a documented format, if we leave? What does that cost? | | |
| How long is our data kept after the contract ends, and how is it deleted? | | |
| Is there a documented API, and is it included in our plan? | | |
| What happens to our data if you are acquired or cease trading? | | |

## Integrations

| Question | Answer |
| --- | --- |
| Which of our integrations do you support out of the box? (bank, payroll, field time, estimating, portals) | |
| Which need custom work, and who builds and maintains it? | |
| Is there single sign-on, and how are leavers removed? | |
